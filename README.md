# Сайт «Хорошее решение» — публикация

## Что это
Статический сайт: index.html (главная), specialists.html, cases.html, blog.html (статьи для SEO), privacy.html (политика), 404.html, admin.html (панель управления, закрыта от индексации и паролем). server.js + package.json — мини-сервер для Railway и другого Node-хостинга.

## Публикация на Railway (основной способ)
1. Railway → New Project → Deploy from GitHub repo → выберите этот репозиторий. Railway сам определит Node-проект и запустит `npm start`.
2. Обязательно добавьте переменные (вкладка **Variables**):
   - `ADMIN_PASSWORD` = пароль от админки. Без неё сайт работает, но /admin.html отвечает «закрыто».
   - `TG_BOT_TOKEN` = токен Telegram-бота (создаётся у @BotFather). Через него форма сайта отправляет заявки. Без токена форма работает в запасном режиме: копирует текст и открывает чат Telegram.
   - `LEAD_MAIN_ID` (необязательно) = user ID основного получателя заявок; по умолчанию зашит в server.js. Дополнительные получатели задаются в админке (Контакты → Заявки с формы). Каждый получатель должен один раз написать боту /start.
   - `ADMIN_HTML_PATH`, `LIVE_DATA_PATH` (необязательно) — нужны только на хостингах, где веб-сервер отдаёт физически существующие файлы напрямую в обход Node (замечено на некоторых тарифах shared-хостинга). Тогда файл админки и файл с данными сайта переносят за пределы публично отдаваемой папки и указывают путь через эти переменные — иначе они станут доступны напрямую по URL, в обход пароля. На Railway не нужны.
3. Вкладка **Settings → Networking → Generate Domain** — получите публичный адрес сайта.
4. Админка: откройте https://ваш-домен/admin.html — браузер спросит логин и пароль. Логин любой (например, admin), пароль — тот, что в ADMIN_PASSWORD.

## Как опубликовать на статическом хостинге (без пароля на админке!)
1. Загрузите ВСЁ содержимое этой папки в корень хостинга (reg.ru, Timeweb, Netlify, GitHub Pages — любой статический хостинг).
2. В canonical/og:url, robots.txt и sitemap.xml прописан домен https://eventspecialists.ru/ — если публикуете под другим доменом, замените эту строку во всех файлах на реальный адрес.
3. Проверьте, что открывается https://домен/ — главная.
4. Внимание: на чисто статическом хостинге (GitHub Pages и т.п.) admin.html НЕ защищена паролем — пароль работает только через server.js (Railway и другой Node-хостинг).

## 404-страница
Файл 404.html подхватывается автоматически на GitHub Pages. На Netlify/Vercel и большинстве хостингов укажите его как error page (или в .htaccess: ErrorDocument 404 /404.html).

## Данные и фотографии
- На хостинге с server.js (Railway, VPS/Beget) правки в админ-панели сохраняются **на сервере**, в файле `.live-data.json` (путь настраивается переменной `LIVE_DATA_PATH`, по умолчанию — рядом с `server.js`). Их сразу видят все посетители сайта, не только тот, кто редактировал.
- При каждом обновлении кода сайта (новый деплой) новые поля из `data.js` автоматически докатываются поверх уже сохранённых на сервере данных — старые правки не «слетают». Логика — в `mergeWithDefaults()` внутри `data.js`.
- Фото профиля специалиста загружается в админке (Специалисты → «Фото профиля») и показывается в каталоге и на странице профиля.
- Вкладка «Экспорт» в админке теперь нужна только для резервной копии (кнопка «Скопировать JSON») или переноса данных между установками сайта — не для публикации, это происходит автоматически.
- На **статическом хостинге** (GitHub Pages и т.п., без server.js) сервера нет — данные по-прежнему сохраняются только в localStorage браузера редактора, как раньше.

## Заявки
Форма и кнопки ведут в Telegram (меняется в админке → «Контакты», сохраняется на сервере автоматически).
